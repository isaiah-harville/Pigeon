# Pigeon v1.2 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship five focused hardening PRs that make message custody, storage recovery, relay compatibility, diagnostics, and releases fail safely.

**Architecture:** Keep each concern on its own branch from `main`. Define small result types at existing boundaries, add failure-path tests before implementation, and avoid protocol or storage migrations beyond the approved scope.

**Tech Stack:** Swift 6/SwiftUI, XCTest, Rust 2024/2021, Tokio/Axum, Cargo, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-12-v1.2-hardening-design.md`

## Global Constraints

- Never log secrets, plaintext, safety material, raw Keychain values, identity fragments, or linkable transport metadata.
- Preserve locked-device delivery without widening Vault or Keychain accessibility.
- No relay acknowledgement until local durable handling succeeds.
- Compatibility is an independent relay wire-protocol range, not component SemVer.
- Keep all protocol/network changes zero-knowledge and fail closed.
